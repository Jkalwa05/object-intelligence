# Hologramm und Seitenleiste Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** A rotatable, true-to-scale 3D hologram per product and a right sidebar with pinned, collapsible entries.

**Architecture:** One Claude call per model (name, category, masked crop) returns primitive parts in millimetres,
cached on disk like profiles and sent as a `shape` message; the browser keeps sidebar entries by card name and renders
the parts with Three.js.

**Tech Stack:** Python 3.12, FastAPI, Pydantic, Anthropic SDK; React 19, TypeScript, zustand, three, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-01-hologram-design.md`

## Global Constraints

- Only object pixels leave the Mac (the same masked crop as for identification); one call per model, ever.
- Shapes only for likely/certain at model depth; every hologram says "vereinfacht · laut Claude".
- No floating card any more; the camera picture never hides behind the sidebar.
- Never call the project a demo.

## Review Focus

- A shape arrives for a name that is no longer the card's name: shown only under its own name.
- Claude returns nonsense sizes (0, negative, metres): clamped or dropped, never a crash or an invisible model.
- More than 8 objects: the oldest entry drops out; the active one is always there.
- The active object leaves: its entry collapses but stays; a manually opened entry stays open.
- WebGL context limits: only expanded entries render a canvas.

### Task 1: Contracts
`oi/contracts.py`, fixture: `ShapePart`, `ProductShape(known, size_mm, parts≤16)`, `ShapeMsg.of(product, status,
shape)`. Tests: message round trip, loading has no parts, fixture (7 messages).

### Task 2: The Claude call
`oi/identify.py`: `ShapeRequest(product, category, jpeg, language)`, `ShapeResult`, `build_shape_request`,
`parse_shape`, `describe_shape` on Claude and Fake identifiers. Tests: image + name in the request, clamping and dropping,
unknown → no parts, cost, fake script.

### Task 3: Caches
`oi/cache.py` generic `JsonCache`; `ProfileStore` and `ShapeStore` on top; `Settings.shape_cache`. Tests: round trip,
restart, broken file, unwritable path (shared tests for both stores).

### Task 4: Pipeline and server
`_want_shape` next to `_want_profile` (crop of the identification), pending/sent per card name, error and budget like
profiles; server and `__main__` share one `ShapeStore` (memory only with `--fake-claude`). Tests mirror the profile
tests.

### Task 5: Browser data
`protocol.ts` (`ShapeMsg`), `store.ts` (`shapes`, `recent`, `open`, `toggleEntry`, `sidebarEntries`), `hud/hologram.ts`
(`partGeometry`, `formatSize`). Tests: entries order/limit/active/open, part geometry, size text.

### Task 6: Browser UI
`hud/Sidebar.tsx`, `hud/Hologram.tsx` (three + OrbitControls), `hud/Overlay.tsx` (name tag, line to the active entry, no
card), `App.tsx` layout, `styles.css`; remove the card placement code. Tests: build, existing tests green.

### Task 7: Real call, visual check, docs, finish
Real `-m claude` shape test, headless render check, README and spec overview, memory, merge, push.
